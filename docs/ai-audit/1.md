# AI adversarial audit — fund extraction

**Date:** 2026-08-11  
**Scope:** `contracts/` Sui Move packages (options protocol, trading vault, RFQ/auction, exchange, adapters, oracles)  
**Goal:** Extract funds that are not intended to be extractable by external attackers (not admin/curator privilege, not known liveness lockups unless they enable theft)  
**Method:** Static review of fund-custody paths + adversarial unit tests that demonstrate live extraction under current code

---

## Executive summary

Two **critical** unauthorized fund-extraction bugs were confirmed in **`trading_vault`**, with passing PoC tests:

| ID | Severity | Finding | Extraction |
|----|----------|---------|------------|
| **CRIT-1** | Critical | Permissionless quote sessions + unreconciled `end_session` | Drain free balances when any quote adapter is enabled |
| **CRIT-2** | Critical | Crank/force sessions allow `take_position` without re-store | Steal custodied positions / option coins; wedge custody shells |

**`options_core` buckets, RFQ/auction, exchange settlement, and `mm_collateral`** did not yield a clean external theft path in this pass.

A prior liveness (non-theft) issue in the legacy `vault` package remains documented in `docs/fund-egress-audit.md`.

PoC tests (both **PASS** = exploit succeeds):

- `trading_vault::quote_session_tests::attack_quote_session_drains_free_balances`
- `trading_vault::vault_tests::attack_crank_session_steals_position`

## CRIT-1 — Quote-session free-balance drain

### Severity

**Critical** — full free-balance drain by any stranger.

### Location

- `contracts/trading-vault/sources/vault.move`
  - `begin_quote_session` (~935)
  - `take` (~999)
  - `end_session` (~1088)

### Root cause

`begin_quote_session` is:

1. **Permissionless** (no `CuratorCap`)
2. **Take-capable** (`forced = false`)

`vault::take` / `vault::put` / `vault::end_session` are **public**. Design docs say adapters must verify a curator-signed fill before value leaves the vault. That check is **not enforced by vault core**: a stranger can open a quote session and call `take` without any adapter entrypoint or signature.

`end_session` only asserts vault id match and emits events. It does **not** require:

- `taken` empty or fully offset by `returned`
- net-zero position counts
- any signed obligation

```move
public fun end_session(vault: &TradingVault, s: Session) {
    let Session { vault_id, adapter, forced, taken, returned, positions_added, positions_removed } =
        s;
    assert!(vault_id == object::id(vault), errors::wrong_vault());
    events::emit_session_settled(/* ... */);
}
```

### Attack path

1. Vault is `Open`.
2. Curator has enabled at least one quote adapter (`add_quote_adapter<W>`) and the protocol allowlists `W`.
3. Attacker mints the public `drop` witness for `W` (e.g. `ExchangeAdapter {}`, or any opted-in adapter).
4. `begin_quote_session(vault, reg, W {})`.
5. `take<T>(vault, session, amount)` for each free balance asset until empty.
6. `end_session` with nothing returned.
7. Transfer balances out as coins.

### Preconditions

| Condition | Required? |
|-----------|-----------|
| Vault `Open` | Yes |
| Quote adapter curator-opted-in + protocol-allowlisted | Yes |
| Free balances > 0 | Yes |
| Signed maker order / FillObligation | **No** |
| Curator presence | **No** |

### Impact

All free balances (accounting asset and any other held coin types). Depositor capital sitting idle, proceeds waiting to be paid, MM inventory not locked in positions.

### PoC

`contracts/trading-vault/tests/quote_session_tests.move` — `attack_quote_session_drains_free_balances`

Existing benign test `quote_session_takes_and_returns_permissionlessly` already exercises take without a signature; the attack is the same path without the “return” half.

### Recommended fix

Prefer in order:

1. **Strong:** Do not expose raw `vault::take` on quote sessions to strangers. Make take/put/end package-private or witness-gated so only audited adapter modules can hold a `Session` that may take.
2. **Obligation-gated take:** Quote sessions may only take against a verified hot potato (e.g. exchange `FillObligation` after signature checks), consumed in the same transaction.
3. **Minimum conservation:** `end_session` aborts unless every taken amount is returned (per type) and position nets are zero — may break multi-step adapter PTBs unless intermediate value stays in potatoes.

Kill switches today (delist adapter, curator remove quote adapter, close vault) stop *new* quote sessions but do not protect a vault that already has quote enabled while Open.

## CRIT-2 — Crank/force-session position theft

### Severity

**Critical** for positions that are themselves valuable objects (`Position`, option `Coin`, reclaimable tickets).  
**High DoS** for module-private custody shells (`DeepBookCustody`, `ExchangeCustody`) — yanking wedges appraisal without easy external drain of nested caps.

### Location

- `contracts/trading-vault/sources/vault.move`
  - `begin_crank_session` (~977) — always available, permissionless, `forced = true`
  - `begin_force_session` (~902) — unlocks when Closing or queue head past grace
  - `take_position` (~1026) — **no `!forced` guard**
  - `end_session` (~1088) — no re-store requirement

### Root cause

Forced sessions correctly block free-balance `take`:

```move
public fun take<T>(/* ... */) {
    assert!(!s.forced, errors::forced_session_take());
    // ...
}
```

But `take_position` has **no forced check**. Crank sessions are explicitly take-less for balances, yet still allow removing any adapter-tagged position. `end_session` does not require the position to be put back.

Adapter witnesses (`VaultMm`, `OptionsAdapter`, `DeepBookAdapter`, `ExchangeAdapter`, …) are public `drop` structs — anyone can mint them.

### Attack path

1. Vault holds positions tagged with adapter `W` (IDs from on-chain events).
2. Attacker: `begin_crank_session(vault, reg, W {})` (always unlocked).
3. `take_position<P>(vault, session, position_id)`.
4. `end_session` without `put_position`.
5. Monetize depending on `P`:

| Position type | Extraction |
|---------------|------------|
| `Coin<C>` (VaultMm option coins) | Transfer / exercise freely |
| `options_core::position::Position` | After expiry, call `bucket::redeem_position` / put twin and claim underlying + settlement |
| Bid/RFQ tickets | May freeze value or enable receive paths depending on layout; at least DoS |
| `DeepBookCustody` / `ExchangeCustody` | Nested caps are module-private → direct withdraw from outside may fail; position gone → appraisal incomplete → withdrawals blocked |

### Preconditions

| Condition | Required? |
|-----------|-----------|
| Any custodied adapter position | Yes |
| Known `position_id` | Yes (events) |
| Vault Closing / grace aged | **No** (crank always works) |
| Curator | **No** |

### Impact

- Direct theft of option inventory and writer positions held for the vault’s strategy.
- Permanent wedge of NAV/appraisal if custody shells or unappraisable objects are removed and not recoverable.
- Forces depositors to rely on incomplete appraisals (blocked exits) even when free balances remain.

### PoC

`contracts/trading-vault/tests/vault_tests.move` — `attack_crank_session_steals_position`

Related intentional test pattern in `delisted_adapter_can_still_be_unwound_by_crank_and_force_sessions` shows crank `take_position` without re-store (destroys a valueless test position). Same API works for valuable types.

### Recommended fix

1. **Block `take_position` when `s.forced`**, mirroring `take`.
2. Keep redeem/settle only on adapter entrypoints that take the position, push proceeds via `put`, and never return the raw position object to the caller (current `vault_mm::redeem_*` / `options_adapter::redeem_*` shape is correct *if* strangers cannot call `vault::take_position` themselves).
3. Optionally assert in `end_session` that `positions_removed <= positions_added` for forced sessions (still weaker than forbidding take).

## Areas reviewed without external fund-extraction findings

### `options_core` (bucket / put_bucket / quote / collateral / position)

- FIFO cursor + offset tombstones + spread ranges appear consistent with pool balances.
- Put cash: ceil collateral in, floor payouts out — designed solvent with admin dust sweep.
- Quote: protocol id, signer id, expiry, nonce, signature schemes; collateral potato is ability-less.
- `write_collateralized` is public but fully collateralized (self-write; no free optionality).
- Collateral release package/module is signed in the quote but selected by PTB composition; safe implementations check `source(request)`; a malicious release can only refuse or spend its own funds, not mint core potatoes.

### `mm_collateral`

- Permissionless deposit; owner-only withdraw; `release` asserts `source == account id`.

### `auction` + `options_rfq`

- Coupled auctions require settle authority witness; RFQ adapters hold that authority.
- Expired/invalidated bucket paths refund bid + escrow.
- Settlement writes through `write_collateralized_balance` with exact escrow amounts.

### `exchange` (order / balance_manager / settlement)

- Domain-separated digests, scheme-prefixed sigs, watermarks, cancel marks.
- Manager binding: maker + manager id must match order.
- Obligation path: provide/collect binding-checked; incomplete obligation aborts whole tx.
- Self-match guarded; debit/credit package-only on funded path.

### Share inflation (`trading_vault`)

- OZ-style virtual `SHARE_OFFSET`; donation attack test asserts attacker loss.
- No seed-deposit requirement documented as intentional because free balances have no anonymous donation path into NAV without appraisal (third-party deposits restricted on exchange BMs similarly).

### Adapter custody encapsulation

- DeepBook: BM + caps live inside `DeepBookCustody`; field privacy prevents arbitrary unpack/withdraw from a yanked object without module functions.
- Exchange: `OwnerCap` similarly module-private.
- **Does not** mitigate CRIT-2 DoS when the position is removed from the vault’s position table.

### Oracles

- Attestation consumers pin asset/quote types and freshness.
- Producers (Pyth/Switchboard/equity poster) are trust/governance surfaces; malicious *allowlisted* oracles can skew NAV (share mint/redeem unfairness) — treated as trust model, not anonymous extraction, unless combined with other bugs.

## Suggested remediation priority

1. **Ship fix for CRIT-1 and CRIT-2 before enabling quote adapters or holding positions in production vaults.**
2. Treat vault core session API as the security boundary: adapters alone cannot be the only gate if `Session` methods are public.
3. Add regression tests that **must fail** after the fix:
   - Quote session take without adapter-verified obligation aborts or cannot leave free balances reduced net of put.
   - Forced/crank `take_position` aborts or end_session aborts if position not restored.
4. Re-audit any new `begin_*_session` variants for the same take/position/end_session pattern.

## Scope limitations

- No mainnet/testnet object crawl; findings are code-level + unit-test PoCs.
- No formal verification of bucket cursor algebra beyond reasoning + existing tests.
- Vendor DeepBook internals reviewed only at adapter boundary.
- CCTP / off-chain relayers / admin key compromise out of scope for “unintended extraction by protocol users.”
- Privileged roles (AdminCap, CuratorCap, external-account release) can move funds by design; not scored as vulns unless they enable *third-party* theft.
